# Збирання прошивок на Windows (build_kit)

Набір збирає варіанти `smartframe.img` для рамки 2 з заморожної бази **v11k** повністю на Windows, без Mac і без LLVM.
Нічого не прошиває: запис лишається окремим кроком (PhoenixSuit).

## Що вміє
| Операція | Параметр | Що змінюється |
|---|---|---|
| Таблиця ініціалізації панелі | `--table ІМ'Я` | Код ініціалізації гілки ID `98 81 1C` у ядрі (таблиці з `data\corpus.json`, список: `--list-tables`) |
| Таймінг панелі | `--timing dclk,ht,hbp,hspw,vt,vbp,vspw` | Таблиця таймінгу `auto_mipi` у ядрі (x=800, y=1280 фіксовані) |
| Затримка перед таблицею | `--pre-delay-ms N` | Пауза перед першою командою (з `--table`) |
| Числові ключі конфігурації | `--set ключ=значення ...` | Наприклад `lcd_dsi_if=2` (у `config_nor.fex` і його копії в пакеті ядра) |
| Дамп регістрів панелі в UART | `--dump-regs` (з `--table`) | Перед ініціалізацією читає сторінки 0–7 (по 256) і друкує в консоль; розбір: `python tools\parse_regdump.py ЖУРНАЛ.log` |
| Драйвер панелі | `--driver ІМ'Я` | `lcd_driver_name`; ім'я має бути зареєстроване в ядрі |

Після кожного збирання автоматично запускається незалежна перевірка (`verify_variant.py`): суми Vmelis, add_sum, Vdata, розпакування ядра, збіг конфігурації, правило `vbp − vspw > 3`, вміщення ядра в слот, перелік змін відносно бази. **PASS означає лише коректну структуру; чи завантажиться образ, показує тільки рамка.**

## Збирання по рамках (основний спосіб)
Дві рамки, різні панелі (`data\frames.json`):
```powershell
python tools\make_variant.py --frame 1 --name <версія> --base <образ інтерфейсу>
python tools\make_variant.py --frame 2 --name <версія> --base <образ інтерфейсу>
```
Без `--base` береться v11k. Результат: `out\F1_<версія>\` або `out\F2_<версія>\`. Рамка 1 = образ інтерфейсу без патчів ядра (інструмент перевіряє, що ядро і конфіг заводські). Рамка 2 = той самий образ + перевірений рецепт (таблиця K101, таймінг 73,890,25,20,1340,20,4). В кінці виводиться `*** FLASH ONLY ON FRAME N ***`. База з уже пропатченим ядром відхиляється. `--frame` не комбінується з параметрами патчів (`--table`, `--timing` тощо): вони лише для експериментів.

## Чого немає (лишається на Mac)
Зміна інтерфейсу (PNG, `lvgl.mod`, мови, заставка), лабораторія таблиць, нові таблиці з вихідників GitHub. Для цього потрібні Pillow, xz, 7zz, LLVM і Linux-вихідники; на Windows не перевірялись.

## Одноразове налаштування
1. **Python 3.8+** (python.org, 64-біт). Перевірка: `python --version`.
2. **liblzma ≥ 5.4** (єдина зовнішня залежність; потрібна для LZMA1EXT, його немає в стандартному модулі `lzma` Python):
   - Якщо в Git for Windows є файл `C:\Program Files\Git\mingw64\bin\liblzma-5.dll`, він знаходиться автоматично (чи версія достатня, покаже `check_env.py`).
   - Інакше: офіційні збірки xz для Windows — `https://github.com/tukaani-project/xz/releases` (файл `xz-<версія>-windows.zip`). Беріть 5.4.x або 5.6.3 і новіші; **не 5.6.0 і 5.6.1** (скомпрометовані релізи). Звірте SHA-256 з даними на сторінці релізу. З архіву скопіюйте `bin_x86-64\liblzma.dll` у `C:\PhotoFrame\build_kit\bin\liblzma.dll` (для 32-бітного Python — `bin_i686`).
   - Або вкажіть шлях вручну: `$env:LZMA_DLL = "C:\шлях\liblzma.dll"`.
3. Перевірка середовища (PowerShell, з `C:\PhotoFrame\build_kit`):
   ```powershell
   python tools\check_env.py
   ```
   Має закінчитись `RESULT  : READY`.
4. Самотест (перезбирає п'ять відомих образів і порівнює з еталонами в `..\firmware`):
   ```powershell
   python tools\selftest_build.py
   ```
   `RESULT: PASS`. `WARN` означає, що байти відрізняються через іншу версію liblzma, але ядро ідентичне: образ коректний. `FAIL` означає, що збирати не можна.

## Використання
Усі команди з `C:\PhotoFrame\build_kit`. Результат — `out\<name>\` (`smartframe.img`, `SHA256SUMS`, `manifest.json`, `verify.txt`). Існуюче ім'я не перезаписується; база не змінюється; при помилці недобудована папка видаляється.

Відтворення відомих образів:
```powershell
python tools\make_variant.py --name r_v12a  --table jieli_ac792_ili9881c_800x1280
python tools\make_variant.py --name r_v12d1 --table jieli_ac792_ili9881c_800x1280 --timing 72,908,56,8,1317,22,6
python tools\make_variant.py --name r_v12d2 --table jieli_ac792_ili9881c_800x1280 --timing 73,908,56,8,1340,26,6
python tools\make_variant.py --name r_v12e1 --table jieli_ac792_ili9881c_800x1280 --timing 72,908,56,8,1317,22,6 --set lcd_dsi_if=2
python tools\make_variant.py --name r_v12e2 --table jieli_ac792_ili9881c_800x1280 --timing 72,908,56,8,1317,22,6 --pre-delay-ms 200
```
Нові варіанти — змінюйте по **одному** параметру відносно відомого образу, щоб результат на рамці був інтерпретований.

Перед записом:
```powershell
Get-FileHash C:\PhotoFrame\build_kit\out\ІМ'Я\smartframe.img -Algorithm SHA256
```

## Обмеження й правила, зашиті в інструменти
- База за замовчуванням `..\firmware\F1_v11k_current_frame1\smartframe.img` (SHA-256 `784eb058…6d81`); інша база лише з `--allow-other-base`.
- Порядок таймінгу в ядрі: dclk, x, y, ht, vt, hbp, **vbp, hspw**, vspw. CLI приймає зручний порядок `dclk,ht,hbp,hspw,vt,vbp,vspw` і сам переставляє. Інструмент відмовляється від `vbp − vspw ≤ 3`.
- Стиснене ядро має вміститись у слот 552 960 Б (запас зазвичай менше 1 КБ); перевірка виводить `free … B`.
- `--no-keep-detect` вимикає автовизначення ID і примусово вмикає таблицю для будь-якої панелі: **тільки для рамки 2**.
- Додати власну таблицю: у `data\corpus.json` додайте запис `"назва": {"packets": [[0xFF,0x98,0x81,стор], [рег,знач], ...], "note": "..."}` (числа десяткові, у JSON hex недопустимий; кожна команда з одним параметром, перемикання сторінки як `[255,152,129,N]`).
